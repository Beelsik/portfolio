Beelsik

Роблю робочу автоматизацію для бізнесу: ботів першої лінії й запису, пошук по внутрішніх документах, розбір рахунків і кошторисів, інтеграції з CRM та ERP.

Нейромережу підключаю лише там, де плаває формат: живий діалог, криві скани, різнобій у назвах позицій. Підрахунок сум, права доступу й запис у базу залишаються у звичайному перевірюваному коді. Нижче — відкритий проєкт LedgerGuard та 11 інтерактивних стендів: можна вставити власне ТЗ, завантажити фото документа або перевірити стійкість бота.

LedgerGuard: перевірка рахунків перед записом у ERP / KeyCRM

Типова ситуація у гуртових, будівельних та інженерних компаніях: менеджери вручну перебивають рахунки з пошти у систему обліку, або підключають «1 промпт у n8n → одразу запис у базу». Обидва підходи втрачають гроші на одних і тих самих деталях: підміна IBAN на інший валідний за модулем 97, ціна на 10% вище договору, арифметика в рядку, плутанина між 3×1,5 і 3×2,5, бухти замість метрів та дублі при повторному листі.

Критерій Було (ручне занесення / 1 промпт) Стало (LedgerGuard, Python 3.12)
Час на документ 12–15 хв вручну; помилки втоми на довгих специфікаціях 2–4 мс автоперевірка (p95: 3,96 мс), <1 хв на розбір у карантині
Приховані помилки в ERP 40,0% на тесті з 60 документів (24/60 пройшли з підміною, переплатою або дублем) 0,0% — усі 24/24 проблемні рахунки зупинено в quarantine_queue
Одиниці й артикули «3 бухти» заходять як 3 м за ціною бухти; плутає 3×1,5 і 3×2,5 100% автопрохід чистих заявок (36/36): розгортає пакування, штрафує чужий переріз

            01Telegram, SIP, KeyCRM, HubSpot

            -- 1. Ізоляція рядків за користувачем та тенантом
ALTER TABLE public.bookings ENABLE ROW LEVEL SECURITY;

CREATE POLICY "tenant_read_own_bookings"
  ON public.bookings FOR SELECT
  USING (customer_id = auth.uid() OR tenant_admin(tenant_id, auth.uid()));

-- 2. Захист від подвійного бронювання на рівні СУБД
CREATE EXTENSION IF NOT EXISTS btree_gist;
ALTER TABLE public.bookings
  ADD CONSTRAINT prevent_double_booking
  EXCLUDE USING gist (staff_id WITH =, slot_range WITH &&)
  WHERE (status <> 'cancelled');

-- 3. Серверний розрахунок вартості (браузер передає лише ID послуги й слот)
CREATE OR REPLACE FUNCTION public.create_booking(p_service uuid, p_slot tstzrange)
RETURNS uuid LANGUAGE plpgsql SECURITY DEFINER SET search_path = public AS $$
DECLARE v_price integer; v_id uuid;
BEGIN
  SELECT price_cents INTO STRICT v_price FROM services WHERE id = p_service AND active;
  INSERT INTO bookings (customer_id, service_id, slot_range, total_cents)
  VALUES (auth.uid(), p_service, p_slot, v_price) RETURNING id INTO v_id;
  RETURN v_id;
END; $$;

            Перевірка бота на prompt injection: один системний промпт проти трирівневого контуру

У вкладці «Промпт (ред.)» можна змінити товари, ціни чи правила й одразу перевірити знову.
